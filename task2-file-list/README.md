# 과제 2: 대용량 파일 목록 UI

## 문제 분석

5,000개 이상의 파일/폴더를 일반 DOM 리스트로 모두 렌더링하면 초기 렌더링과 스크롤 성능이 크게 나빠집니다. 특히 트리 모드에서는 폴더 펼침 상태에 따라 보이는 항목 수가 크게 변하므로, 플랫 리스트와 트리 리스트 모두 가상 스크롤이 필요합니다.

## 기술적 선택

- `react-window` v2의 `List`, `Grid`를 사용해 리스트/그리드 모두 가상화했습니다.
- 이 과제는 백엔드 API가 필요 없다는 요구사항에 맞춰 MSW를 사용하지 않고 프론트엔드에서 mock 데이터를 생성합니다.
- 4-depth 트리 구조와 10,000개 파일이 들어있는 현재 폴더를 함께 구성해 플랫 모드와 트리 모드 성능을 모두 확인할 수 있게 했습니다.
- 다중 선택은 Ctrl/Cmd 클릭과 Shift 클릭 범위 선택으로 구현했습니다.
- 드래그앤드롭 이동은 실제 파일 시스템이 아니라 `parentId` 상태만 변경합니다.

## 구현 기능

- 18,000개 이상의 파일/폴더 mock 데이터
- 3~4 depth 폴더 트리
- Breadcrumb 및 현재 위치 표시
- 플랫 모드: 현재 폴더 내 10,000개 항목 가상 스크롤
- 트리 모드: 펼쳐진 부모/자식 항목 가상 스크롤
- 파일 타입 필터, 검색 및 하이라이팅, 이름/크기/수정일 정렬
- 리스트/그리드 뷰 전환
- 선택 항목 수와 총 크기 표시
- 선택 삭제 및 드래그앤드롭 이동

## 아키텍처

- `src/main.tsx`: 앱 진입점
- `src/App.tsx`: 트리/플랫 뷰, 선택, 드래그앤드롭, 가상 스크롤 UI
- `src/mockData.ts`: 대용량 로컬 mock 데이터 생성
- `src/styles.css`: 목록형 스토리지 UI 스타일

## 성능 측정

로컬 개발 환경 기준:

- 전체 mock 데이터: 18,380개
- 플랫 모드 현재 폴더: 10,000개
- `react-window` overscan 적용 시 실제 DOM row는 viewport 주변 수십 개 수준으로 유지됩니다.
- Chrome DevTools Performance에서 빠른 스크롤 중 DOM 노드 수가 전체 데이터 수와 비례해 증가하지 않는 것을 확인했습니다.
- 목표: 10,000개 항목에서도 60fps에 가깝게 스크롤되도록 고정 행 높이와 memoized derived data를 사용했습니다.

## 개선하고 싶은 부분

- 폴더별 하위 항목 수와 집계 용량을 캐싱하면 더 큰 데이터에서도 트리 탐색 비용을 줄일 수 있습니다.
- 드래그 중 ghost preview와 키보드 접근성을 더 정교하게 만들 수 있습니다.
- 실제 서비스라면 서버 페이지네이션 또는 검색 인덱스를 결합할 수 있습니다.
